利用方法

Codexを安全に、再現性高く使うための基本操作と運用ルールです。

はじめ方

  1. 対象リポジトリのルート、または作業したいサブディレクトリでCodexを起動します。
  2. 初回はChatGPTアカウントまたはAPIキーで認証します。
  3. 最初の依頼では、目的、対象範囲、完了条件、実行してよい検証コマンドを伝えます。
codex

CLIではローカルの選択ディレクトリを読み、必要に応じてファイル編集やコマンド実行を行います。大きな変更を任せる前に、まず調査だけを依頼すると状況をそろえやすくなります。

依頼の書き方

含める情報例
目的「ログイン後のダッシュボード表示が遅い原因を調べて」
範囲「まず src/dashboard 配下だけ見て」
制約「API仕様は変えない」「既存のUIコンポーネントを使う」
検証「変更後に npm test と npm run lint を実行」
成果物「原因、変更点、残リスクを最後に短くまとめて」

良い依頼の型

このリポジトリでユーザー一覧の検索条件を追加してください。
対象は src/users 配下です。
既存のAPIレスポンス形式は変えないでください。
実装後に関連テストを追加し、実行結果を教えてください。

カスタマイズの使い分け

仕組み使う場面置き場所の例
AGENTS.mdリポジトリの恒久ルール、テスト手順、レビュー観点を共有するリポジトリルート、またはサブディレクトリ
Skill繰り返す作業手順をCodexに覚えさせる.agents/skills/<name>/SKILL.md
PluginSkill、外部アプリ連携、MCP設定をまとめて配布するCodexのPluginディレクトリ、Marketplace
MCP外部ツール、社内データ、専用コマンドをCodexから使わせる~/.codex/config.toml など

判断基準は「一回きりならプロンプト」「チーム標準ならAGENTS.md」「手順ならSkill」「配布や外部連携を含むならPlugin」です。

安全運用

  • 破壊的な操作、外部送信、認証が絡む操作は、承認内容を読んでから許可します。
  • 機密情報はプロンプトへ直接貼らず、必要最小限のファイルや接続権限で扱います。
  • 生成された差分は git diff で確認し、テスト結果とセットでレビューします。
  • 外部サービスPluginは、サービス側の利用規約、プライバシー、共有範囲も確認します。
