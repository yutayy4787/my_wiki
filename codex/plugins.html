おすすめプラグイン

PluginはSkills、外部アプリ連携、MCPサーバーをまとめてCodexへ追加する仕組みです。単体のSkillで足りる作業と、Plugin化すべき作業を分けて考えます。

目次 利用方法 利用例 チートシート おすすめプラグイン GSD導入 GSD利用手順 GSDチートシート GSD活用例

導入方針

  1. まずは業務上必要なPluginだけ入れます。迷う場合は単体のSkillから始めます。
  2. 外部サービス接続は、認証アカウントと共有範囲を確認します。
  3. インストール後は新しいスレッドでPlugin名、目的、対象データを明示して試します。

Pluginを入れても、承認設定は別途適用されます。外部サービスへ送られるデータは、そのサービス側の規約とプライバシーポリシーにも従います。

Plugin、Skills、MCPの使い分け

仕組み向いていること判断基準
Skillレビュー手順、リリースノート生成、調査テンプレートなどの再利用できる作業手順SKILL.md と必要な参照資料、スクリプトで完結するならSkillで十分
PluginSkill、アプリ連携、MCP、Hooks、アセットをまとめて配布するワークフローチームへインストール可能な形で配りたい、外部連携も一緒に渡したい場合
MCP社内API、検索、DB、チケット管理など、Codexが使う外部ツールを増やす手順ではなく、Codexが呼び出す道具やデータソースが必要な場合
Apps / ConnectorsGoogle Drive、Slack、Gmailなど、認証付き外部サービスを扱うユーザーやワークスペースの権限で外部データへアクセスする場合
Hooksコマンド実行や編集前後のチェックを自動化する「必ず実行する」機械的なガードを入れたい場合
Security

Codex Security

認可されたコードをスキャンし、脆弱性らしい指摘を確認し、修正案を作る用途に向きます。

  • PRレビュー前のセキュリティ観点チェック
  • 依存関係更新後のリスク確認
  • 脆弱性バックログの一次整理
Documents

Google Drive

Drive、Docs、Sheets、Slides上の資料を参照しながら、仕様整理やレポート作成を進める用途に向きます。

  • 最新仕様書の読み取り
  • スプレッドシートの要約
  • 議事録から実装タスクを抽出
Communication

Slack

チャンネル要約、スレッド整理、返信ドラフト作成など、開発コミュニケーションの整理に使います。

  • 障害対応チャンネルの時系列整理
  • 未対応質問の抽出
  • リリース連絡文の下書き
Mail

Gmail

メールの検索、要約、返信ドラフト作成が必要なチームで有効です。

  • 重要な未読メールの抽出
  • 問い合わせ内容の分類
  • 返信文の下書き作成
Web Apps

Sites

Webサイト、社内アプリ、ゲームなどをCodexで作成し、ホストされた形で共有したいときに使います。

  • 社内ツールのプロトタイプ
  • 静的サイトの作成と公開
  • 検証用UIの共有
Team Workflow

自作Plugin

チーム固有のSkill、MCP、外部アプリ連携をまとめて配布したい場合は自作Pluginにします。

  • リリースノート生成
  • 社内レビュー標準の適用
  • 業務システムMCPとの接続

まず作りたいSkills

Skill狙い含めたいルール
差分レビューSkillレビューの観点、重大度、出力形式、確認コマンドを固定セキュリティ、互換性、テスト不足を優先し、ファイルと行番号、残リスクを書く
ドキュメント更新Skill仕様変更からREADME、社内Wiki、リリースノートの更新漏れを検出既存の文体と見出し構造に合わせ、古い手順やスクリーンショットを探す
リリース準備Skill差分、Issue、PR、テスト結果からリリース前チェックを整理破壊的変更、移行手順、ロールバック案、未確認項目を分ける
調査レポートSkill原因調査や技術選定を、根拠と未確認事項つきで整理編集前に仮説、確認方法、根拠を分離し、一次情報を優先する

自作Pluginの最小構成

Pluginとして配る場合は、ルート直下にSkillやMCP設定を置き、.codex-plugin/plugin.json から参照します。

team-workflows/
  .codex-plugin/
    plugin.json
  skills/
    diff-review/
      SKILL.md
    release-notes/
      SKILL.md
  .mcp.json
  hooks/
    hooks.json
  assets/
    icon.png

Pluginの識別子になる name は安定したkebab-caseにし、skills、mcpServers、apps、hooks はPluginルートからの相対パスで指定します。

使い始めの依頼例

  • @google-drive を使って、このフォルダの最新仕様書を要約してください。
  • @slack を使って、昨日からの障害対応スレッドを時系列で整理してください。
  • Codex Security pluginで現在の差分にセキュリティ上の問題がないか確認してください。
  • @diff-review のSkillで、現在の差分を重大度順にレビューしてください。
  • /skills で使えるSkillを確認し、今回のリリース準備に合うものを選んでください。
