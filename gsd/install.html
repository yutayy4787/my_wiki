GSD Coreとは

GSD Core（Git. Ship. Done.）は、要件、ロードマップ、実装計画、検証結果をファイルに残しながら、Codexの調査・計画・実装をフェーズ単位で進める仕組みです。長い会話だけに状態を持たせず、プロジェクト内の .planning/ を継続的な記録として使います。

このWikiでは、現在メンテナンスされている @opengsd/gsd-core を標準とします。CodexではGSDコマンドがSkillとして入り、$gsd-help のように呼び出します。

必要な環境

項目条件確認
Node.js18以上。インストーラーの実行に必要node --version
npm / npxNode.jsに付属する現行版npx --version
Codex CLI0.130.0以上。Hook連携を含めるなら0.137.0以上を推奨codex --version
Git対象プロジェクトがGitリポジトリであることを推奨git status

インストーラーはCodexのSkill、エージェント設定、Hook設定をランタイム向けに変換します。GitHubリポジトリからファイルを直接コピーしないでください。

インストール

全プロジェクトで使う

npx @opengsd/gsd-core@latest --codex --global

個人環境へ入れる標準的な方法です。Skillは ~/.codex/skills/gsd-*/SKILL.md に入り、Codexの設定へGSD用エージェントとHookが追加されます。

現在のプロジェクトだけで使う

cd /path/to/project
npx @opengsd/gsd-core@latest --codex --local

チームで同じGSD構成を共有したい場合や、個人設定へ影響させたくない場合に使います。生成物をGit管理するかは、内容とチーム方針を確認して決めてください。

方式向いている場面注意点
--global自分が複数のリポジトリでGSDを使う個人のCodex設定全体へ適用される
--local特定リポジトリだけで使う、チーム導入を試す対象リポジトリの設定と既存ファイルを確認する

導入確認

  1. インストーラーがエラーなく終了したことを確認します。
  2. 実行中のCodexを終了して再起動します。対応版では codex --reload も利用できます。
  3. 対象リポジトリでCodexを起動し、GSDのヘルプを呼び出します。
cd /path/to/project
codex

# Codexの入力欄
$gsd-help

候補が表示されない場合は、/skills または入力欄で $ を入力し、gsd- で始まるSkillを探します。

更新と削除

更新

npx @opengsd/gsd-core@latest --codex --global

インストーラーは再実行可能です。Codex内からは $gsd-update でも更新を確認できます。更新後はCodexを再起動します。

アンインストール

npx @opengsd/gsd-core@latest --codex --global --uninstall

# ローカル導入を削除する場合
npx @opengsd/gsd-core@latest --codex --local --uninstall

GSDが管理するSkill、エージェント、Hookを削除します。プロジェクトの .planning/ を削除する場合は、必要な履歴が残っているか別途確認してください。

旧版との混同に注意

旧 gsd-build/get-shit-done はアーカイブされ、開発先は open-gsd/gsd-core へ移っています。旧 get-shit-done-cc や非推奨の移行途中パッケージではなく、@opengsd/gsd-core を使います。

Codex専用Forkも存在しますが、通常利用ではCodexを正式サポートするGSD Coreを優先します。既存環境から切り替える場合は、旧GSDをアンインストールしてからGSD Coreを導入し、Skillの重複がないことを確認してください。
